# Telegram Job Hunter

Личный Telegram-бот для поиска аналитических вакансий по 50 карьерным источникам: hh.ru RSS (или OAuth API), Хабр Карьера RSS, Geekjob, Aviasales, международные доски и страницы компаний на Ashby/Lever/Greenhouse.

## Условия поиска

**Широкий поиск аналитики:** продуктовая, коммерческая, бизнес-, финансовая, маркетинговая, операционная, data/BI-, e-commerce-, growth-, revenue- и игровая аналитика, а также общие роли «Аналитик» и «Analyst». Приоритет — удалёнка из любой страны; русскоязычная команда желательна, английские объявления допустимы. Ориентир — 250–300 тыс. ₽ net. Фильтр требует признак удалёнки и отсеивает явные ограничения по стране, а также банки, системную аналитику и инженерные роли DWH/ETL. Известные зарплаты с верхней границей ниже 250 тыс. ₽ исключаются. Более высокие зарплаты не исключаются. Неизвестная зарплата и валюта без пересчёта помечаются для проверки.

Это подборка кандидатов, а не гарантия совпадения: русский текст не доказывает язык команды, «удалённо» не гарантирует отсутствие поездок или право работать из любой страны, gross не пересчитывается в net. Нет доступа к истории ChatGPT или встроенному веб-поиску ChatGPT. Свой файл резюме можно загрузить отдельно через Telegram. Getmatch и Telegram-каналы пока не подключены. Результаты ограничены выдачей источников (Хабр — до 50 последних записей RSS на один из трёх запросов, Geekjob — первая страница поиска); это не полный индекс интернета.

## Команды

- `/start` — подписка на автоматическую проверку.
- `/check` — до 15 ещё не отправленных вакансий; автоматическая рассылка ограничена 10 сообщениями за цикл.
- `/more` — следующая порция.
- `/sources` — сколько получено и отфильтровано, ошибки по каждому источнику и время проверки.
- `/profile` — текущие условия отбора.
- `/stop` — отключить подписку.
- `/resume` — загрузить резюме PDF/DOCX/TXT.
- `/forget_resume` — удалить сохранённый текст резюме.
- `/applications` — история откликов и их статусы.
- `/top` — повторно показать пять самых подходящих вакансий, включая ранее отправленные, с интерактивными кнопками.
- `/ai_on` и `/ai_off` — дать или отозвать согласие на запросы в AI API.

Источник с HTTP 403 помечается недоступным; остальные продолжают работать. Если недоступны все, бот сообщает об ошибке, а не об отсутствии вакансий. Подборка кешируется в SQLite на 6 часов, при полном отказе — на 15 минут. Кеш сохраняется после рестарта. Повторные команды не создают лишние запросы к площадкам. Доставка учитывается для каждого chat_id только после успешной отправки. Ручная и автоматическая проверки защищены общим lock.

## Запуск

Python 3.12. Установите `pip install -r requirements.txt`. Скопируйте `.env.example` в `.env`, задайте `TELEGRAM_BOT_TOKEN` и числовой `ALLOWED_CHAT_ID` до запуска. Запустите `python main.py`. Без разрешённого chat_id бот не запускается. Токен не коммитьте.

## Railway

Сервис из `yamarc227-ai/telegram-job-hunter`, ветка `main`. Dockerfile автоматически устанавливает зависимости и запускает `python main.py`. В Variables задайте `TELEGRAM_BOT_TOKEN`, `ALLOWED_CHAT_ID`, `SEARCH_INTERVAL_HOURS=6` (минимум 6 часов). Подключите Volume к `/data`; база хранится по `RAILWAY_VOLUME_MOUNT_PATH`. Одна реплика, Serverless отключён, Restart Policy On Failure. Домен и HTTP healthcheck не требуются. После старта отправьте `/start` и `/check`.

При первом переходе со старого прототипа таблица подписок сохраняется. Новая история отправок ведётся отдельно от старой глобальной таблицы `seen`, поэтому ранее полученная вакансия может прийти один раз повторно. Старый ZIP оставлен как архив исходного MVP и не используется при запуске.

## Проверки

`python -m unittest -v` — фильтры зарплаты/специализации, частичный отказ источников, сохранение кеша, дедупликация, повтор после неудачной доставки и честный ответ при полном отказе источников. Для проверки доступности без Telegram: `python -c "import asyncio; from sources import collect; print(asyncio.run(collect())[1])"`.

### Доступ к hh.ru

Поиск hh использует OAuth: в Railway → сервис → Variables добавьте `HH_ACCESS_TOKEN`
со значением access_token вашего разрешённого приложения hh. Получение и просмотр
токена: https://dev.hh.ru/admin ; документация:
https://github.com/hhru/api/blob/master/docs/authorization_for_application.md .
Не записывайте токен в репозиторий и не отправляйте его в чат.
После применения переменной Railway перезапустит сервис; кэш поиска обновится
при изменении токена. Проверьте `/sources` в Telegram.
Без токена hh пропускается с явным сообщением; другие источники работают.
Наличие токена не гарантирует права: если hh отказывает и с ним, проверьте доступ
приложения в кабинете hh. Истёкший пользовательский токен нужно заменить;
автоматическое обновление пользовательских OAuth-токенов не реализовано.

## Обновление источников (18 октября 2026)

Добавлены **Remotive** (публичный API), **Remote OK** (JSON API), **We Work Remotely** (RSS) и **Arbeitnow** (публичный API). Сохранились Aviasales, Хабр Карьера и Geekjob.

### hh.ru

- Без OAuth: `HH_MODE=rss` (по умолчанию). Бот читает RSS `/search/vacancy/rss`. Сервис может вернуть 403, 429 или капчу; в этом случае источник помечается как недоступный и остальные работают дальше.
- С разрешённым OAuth: `HH_MODE=api` и `HH_ACCESS_TOKEN` в Railway Variables. Дополнительно можно задать `HH_USER_AGENT` с реальным контактом разработчика.
- HTML-парсинг hh.ru, обход капчи и других ограничений доступа не используются. Работоспособность RSS с Railway пока не подтверждена.

### Работа с источниками

- Проверка каждые 6 часов (ограничение Remotive: рекомендовано не больше четырёх запросов за сутки). Не запускать несколько реплик бота.
- Англоязычные объявления больше не отсеиваются только по языку. Русский рабочий язык и возможность работать из любой страны всё ещё нужно подтверждать.
- Статус `worldwide remote` показывается при соответствующем поле площадки; прочие вакансии помечаются как требующие уточнения.
- Не пересчитываются автоматически gross/net и валюты. Фильтры зарплат — предварительные.
- Для диагностики: `/sources` и `/check` в Telegram, Railway Logs.
- `python -m unittest -v` — тесты на искусственных ответах источников, не живая проверка сети.

Не публикуйте файл `.env` и токены в GitHub; используйте Railway Variables.

## Карьерные страницы компаний: 42 источника

Файл `ats_boards.json` содержит 42 страницы работодателей, в том числе Higgsfield AI, Air Apps, Rwazi, OpenAI, ElevenLabs, Figma, Notion, PostHog, Spotify, Airbnb и другие.

Поддерживаемые публичные ATS: **Ashby** (25 компаний), **Lever** (9) и **Greenhouse** (8). В сумме с восемью общими источниками бот проверяет 50 независимых лент/карьерных досок. Наличие страницы не означает, что прямо сейчас на ней есть открытая подходящая вакансия.

Все вакансии проверяются на слова «аналитик / analyst», специализацию и удалённый формат. OnSite/Hybrid по Ashby или Lever не выдаются за remote; Greenhouse учитывает признак удалённости только в названии должности или географическом поле. У некоторых объявлений работа «remote» ограничена конкретной страной: географию необходимо проверять перед откликом.

Площадки опрашиваются с максимум пятью одновременными запросами. Сбой одной карьерной доски не останавливает остальные. Команда `/sources` показывает сводку по ATS и первые несколько ошибок; полный перечень ошибок доступен в Railway Logs.

Если нужно добавить работодателя, у которого карьерная страница находится на `jobs.ashbyhq.com/<slug>`, `jobs.lever.co/<slug>` или `boards.greenhouse.io/<slug>`, добавь объект `{"ats":"ashby|lever|greenhouse","company":"Название","slug":"slug"}` в `ats_boards.json`. Для нового провайдера требуется отдельный парсер.

Запуск тестов: `python -m unittest -v`. Для автоматической публикации из GitHub в Railway необходимо, чтобы сервис был подключён к репозиторию и была включена настройка авторазвёртывания.

Адреса семи недоступных досок были заменены после проверки журналов Railway: добавлены Mindly, Photoroom, Toogeza, Peek, Glow25, Paddle и Progress Partners. Расширение или изменение списка компаний не гарантирует наличие удалённых вакансий, соответствующих твоим условиям.

## Три уровня соответствия вакансий

Бот показывает предварительную **эвристическую** оценку совпадения задач с опытом пользователя в Ozon Fresh, а не вероятность получить оффер:

1. **🎯 Идеально подходят по задачам** — профильная продуктовая, бизнес-, коммерческая, growth-, игровая или e-commerce аналитика, плюс минимум два подтверждённых в тексте сигнала подходящих инструментов/метрик (SQL, Python, GMV, retention, когорты, конверсия и т. п.). Название категории не означает, что совпадают seniority, гражданство, налогообложение, зарплата или рабочая страна.
2. **🔎 Стоит рассмотреть** — Data/BI Analyst, профильная аналитика с коротким описанием, либо другие аналитические вакансии со значимым пересечением задач.
3. **🧩 Смежная аналитика** — общие, финансовые, операционные и похожие роли с небольшим подтверждённым пересечением задач.

Сортировка: сначала категория, затем балл соответствия, затем приоритет широкого remote и свежесть объявления. Бот не использует LLM и не запрашивает платные API для оценок. Баллы 0–100 рассчитаны по тексту и могут измениться после уточнения требований.

Команда **/tiers** показывает, сколько уникальных вакансий попало в каждую категорию в текущем кэше. **/check** и **/more** показывают категорию, балл и до трёх причин в каждой карточке. Известные географические ограничения и банки по-прежнему исключаются до классификации. Количество отправляемых сообщений: 15 за ручную проверку и 10 за плановый опрос; отправленные ссылки повторно не присылаются.

Тестирование: `python -m unittest -v`, включая отдельные тесты категорий и осторожного обращения с неизвестными условиями.


## Персональный карьерный помощник: версия 0.8

Под каждой вакансией есть кнопки:
- 👍 Нравится / 👎 Не подходит — сохраняют предпочтения. Похожие вакансии учитываются при сортировке; дизлайкнутую ссылку бот не повторяет.
- 📌 В избранное / ✅ Откликнулся — сохраняют этап. Команда `/applications` показывает позиции, позволяет отметить HR, интервью, оффер, отказ.
- 🤖 Анализ — сравнение вакансии и загруженного резюме. Без OpenAI API это локальный поиск совпадающих навыков, а не AI-анализ.
- 📄 Резюме — DOCX и PDF: без AI сохраняет исходные факты и оформляет черновик, с AI делает адаптацию под вакансию. Любой черновик проверяй перед отправкой.
- ✉️ Письмо — сопроводительное письмо, на основе подтверждённой информации из резюме.

### Загрузка резюме

Отправь `/resume`, затем файл PDF, DOCX или TXT не более 5 МБ. Извлечённый текст хранится в SQLite на томе Railway `/data`, **не в GitHub**. Из PDF-сканов без текстового слоя текст не извлекается; пришли DOCX. Для удаления используй `/forget_resume`. Файлы, присланные ботом в Telegram, остаются в истории Telegram, пока ты сам их не удалишь.

### Подключение AI

Для платного AI добавь `OPENAI_API_KEY` в Railway Variables (не в GitHub/Telegram), при желании `OPENAI_MODEL=gpt-4.1-mini`. Подписка ChatGPT не заменяет отдельный API-ключ. Даже с ключом данные никуда не отправляются до явного согласия через `/ai_on`. После согласия каждое нажатие 🤖/📄/✉️ отправляет извлечённый текст резюме и описание выбранной вакансии в OpenAI Responses API (`store=false`). Это может расходовать API-баланс. `/ai_off` запрещает последующие вызовы. Генерация не гарантирует отсутствие ошибок, любые даты, компании, достижения и контакты нужно проверить.

### Ограничения

- Доступ к новым действиям возможен только через чат `ALLOWED_CHAT_ID`.
- Локальные функции, рекомендации и трекер работают без OPENAI_API_KEY.
- История хранится между обновлениями в базе SQLite на Railway Volume, если том не удалён.
- Автооткликов нет: кнопка «Откликнулся» вручную записывает статус.
- Генерация русскоязычных PDF требует системного пакета `fonts-dejavu-core` (установлен в Dockerfile).
- Автоматические тесты: `python -m unittest -v`; они не выполняют внешних API-вызовов.
